# 개발 — 시뮬레이션과 화면을 나누기

ispacecraft는 TypeScript로 시뮬레이션과 브라우저 앱을 개발하며 Three.js로 3D 장면을 표현합니다. 이 문서는 구현 구조와 개발 원칙을 설명합니다. 앱 소스는 별도 비공개 저장소에서 관리합니다.

## 구조

| 구성 | 책임 |
|---|---|
| 시뮬레이션 | 이동·비행·궤도·생존·자원·장비 상태 계산 |
| 브라우저 앱 | 입력, 화면, 3D 표현, 소리, 저장과 사용자 설정 |
| 협동 연결 | 방 생성·참가와 연결 정보 교환, 참가자 상태 전달 |
| 정적 배포 | 브라우저 앱과 공개 자료 제공 |

화면의 애니메이션이 재고나 물리 상태를 임의로 확정하지 않도록 계산과 표현의 책임을 나눕니다. 장비 동작의 진행 상태를 시뮬레이션이 정하면 렌더러가 그 상태를 외형과 효과로 보여 줍니다.

## 화면 없이 검증하는 규칙

비행·착륙·채굴·생존 규칙은 화면 없이도 실행할 수 있는 구조로 검사합니다. 저장과 재개 중 광석이 중복 지급되지 않는지, 착륙 능력이 부족한 상태에서 자동 착륙이 허용되지 않는지 같은 결과가 검증 대상입니다.

브라우저에서는 이동·착석·분사·저장·불러오기 등 실제 사용자 흐름과 화면 오류를 확인합니다. 타입 검사와 정적 검사, 빌드는 별도로 수행합니다. 통과한 검사가 곧 모든 기기의 성능이나 모든 상황의 안전성을 보장하지는 않습니다.

## 재현성과 저장

시드와 시간에 따라 생성·계산되는 세계를 다루고, 저장 형식이 바뀔 때 이전 진행을 읽는 경로를 고려합니다. 사용자가 보는 효과 품질과 세계의 자원·장비 상태가 서로 다른 결과를 만들지 않도록 구분합니다.

현재 저장의 중심은 기기와 브라우저입니다. 클라우드 계정 동기화나 서버가 관리하는 지속 우주를 제공한다는 뜻은 아닙니다.

## 개발 방식

기획·설계·결정 이유를 문서에 남기고, AI 에이전트가 구현하며 프로젝트 오너가 검토합니다. 시안은 검토 자료이며 선택되기 전에는 확정 디자인으로 취급하지 않습니다. 작은 변경을 검증하고 통합하는 방식으로 발전시킵니다.

엔진 교체, Rust/Wasm, WebGPU 등은 장래 검토 대상입니다. 현재 채택된 구현으로 소개하지 않습니다.
